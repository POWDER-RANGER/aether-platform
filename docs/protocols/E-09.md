# E-09 — Session reliability and stall diagnosis

**Status:** UNVERIFIED  
Tool state: implemented; owner hardware execution remains UNVERIFIED  
**Threshold:** **PROPOSED, NOT FROZEN:** 30 minutes per session, 10/10 sessions.

## Purpose

Support the M1 item to diagnose previously observed gameplay stalls and unexpected exits. The harness captures process output and exit status, monitors a heartbeat written by the companion's main loop, requests a Python stack dump through the child's faulthandler hook after a stale heartbeat, and preserves the recording event stream for recovery-stall inspection.

## MSI procedure

From the repository root:

\`\`\`powershell
python scripts/soak/run_session.py --settings configuration/platform/ENV-01.yaml --minutes 30 --heartbeat-timeout 10 --repeat 10
\`\`\`

The child runs \`python -m aether.cli_ext companion --settings ...\`. The harness writes one session record at \`evidence/E-09/<run_id>.json\`, logs under \`evidence/E-09/<run_id>/\`, and a repeat summary under \`evidence/E-09/summary-<timestamp>.json\`.

## Classification

- \`completed\`: requested duration elapsed and child stopped normally.
- \`crashed(<exit_code>)\`: child exited unexpectedly with a non-zero exit code.
- \`hung\`: no main-loop heartbeat arrived within the configured timeout; stack dump requested, then child stopped.
- \`stalled\`: recording contains a \`recovery.stall\` event and the session otherwise completed.

## What to record

Preserve the JSON session record, stdout, stderr, faulthandler output, heartbeat timestamps, recording manifest, and \`events.jsonl\`. Record exact settings, ENV-01, git revision, Windows/GPU/driver versions and any observed player intervention.

## Defect-resolution rule

A defect is **RESOLVED** only after a reproduced cause, evidence-backed diagnosis, fix, and ten subsequent clean runs. Ten runs without a reproduced cause do not prove a previously observed defect was fixed. The proposed 10-session milestone is not a frozen threshold.

## Limitations

The child process/hardware path is UNVERIFIED until executed on the owner's MSI. The harness does not manufacture gameplay, frame, or stall data; if no recording event exists, it records that absence. A heartbeat indicates companion main-loop progress, not proof of successful gameplay.
