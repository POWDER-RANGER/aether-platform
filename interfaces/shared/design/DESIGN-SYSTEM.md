Version 0.2, 2026-10-26. Built on `docs/vision/BRAND.md` v1 (carried over from the retired reference codebase, provenance in §2). BRAND.md owns names, voice, materials and the logo. This file owns tokens, components, status vocabulary, layout and the build.

| File | Role |
| --- | --- |
| `interfaces/shared/design/tokens.json` | Single source of every value |
| `interfaces/shared/design/tokens.css` | Generated by `scripts/brand/build_tokens.py`; do not edit |
| `interfaces/shared/design/components.css` | Primitives, status components, patterns, application shell |
| `interfaces/shared/design/gallery.html` | Reference page; every component with real data or inside a DEMO ONLY frame |
| `tests/interfaces/test_design_tokens.py` | Fails if the CSS is stale, a contrast pair fails, or the status vocabulary drifts from the project instructions |

Status: tokens, generator, tests, components and gallery are **VERIFIED** (§10). No Æther product surface uses them yet: product views are **NOT IMPLEMENTED**.

## 1. Principles

1. **Say only what has run.** Every capability on screen carries an evidence status (§4). Every number names its source. Mock data appears only inside a DEMO ONLY frame.
2. **The player always sees who is in control and can always stop.** On player surfaces the control state and stop control are always visible and never smaller than 56px.
3. **One plate, three identities.** Æther, PR-REX and AACP share every token except the accent; they differ by accent, kicker label and content, not by separate component sets.
4. **Accessibility is the product.** WCAG 2.2 AA is the floor everywhere; player surfaces go further (§7).
5. **Restrained in the application, industrial in the identity.** The steel-and-maroon identity (owner direction, 2026-10-22) lives in the wordmark, banners and site hero. Application surfaces use flat plates, hairlines and one accent: no glow, no textures, no decorative motion (D-011).
6. **Local-first, no build step.** Plain CSS custom properties and static HTML; the token build is standard-library Python.

## 3. Foundations

- **Base** `#150809` for every UI surface; `#0c0405` is `--ink` for shadows, log wells and artwork only (D-002).
- **Light status colors** corrected to pass 4.5:1: `--ok #24663a`, `--warn #7d5200` (D-003).
- **Product accents** (D-004): Æther `#f2c230` (existing), PR-REX `#d9a9ad` (existing artwork rose), AACP `#8fb3c9` (new). Light: `#8a1c26`, `#8a3a44`, `#2f5a73`. Set with `data-product` on a container.
- **Space** 4px base: 4, 8, 12, 16, 24, 32, 48, 64, 96. **Corners** square; radius only on the focus ring.
- **Type** per BRAND.md §3: Big Shoulders Display (display), Helvetica Neue stack (text), system monospace (labels, identifiers, timestamps, values).
- **Theme** follows the OS; `data-theme="dark"` or `"light"` on `<html>` pins it.
- **Contrast** 40 declared pairs are computed by the build and must pass.

## 4. Status vocabulary

Three closed sets; extending one is a recorded decision.

**Evidence status** (`.status[data-status]`), exactly the six classifications of the project instructions §10:

| Label | Meaning | Mark |
| --- | --- | --- |
| VERIFIED | Directly supported by reproducible evidence | filled square |
| PARTIALLY VERIFIED | Some functionality works; conditions or coverage incomplete | half square |
| UNVERIFIED | Not yet tested adequately | hollow square |
| FAILED | A test showed the requirement is not met | cross |
| BLOCKED | Verification cannot proceed; the dependency is named | bar |
| NOT IMPLEMENTED | Does not exist yet | dashed square |

**Operational state** (`.op[data-op]`): UNAVAILABLE, AVAILABLE, ENABLED, AUTHORIZED, ACTIVE, EXECUTING, COMPLETED, FAILED. Each has its own mark; no single green light stands for several.

**Control state** (`.control[data-control]`): PLAYER, PR-REX, NEUTRAL, HALTED. Mirrors the Governor's report; a surface never infers it.

Related: **Stop** (`.stop`, ≥56px, triggers the existing stop path, never a second one); **Mode banner** (`.mode`, names Research Mode or Companion Mode and the environment ID on every Æther and PR-REX screen); **Demo frame** (`.demo-frame`, dashed, labeled DEMO ONLY · NOT LIVE DATA).

Intended, commanded, delivered and observed actions are separate fields wherever an action is shown; no surface merges them into one "done".

## 6. Product surfaces (NOT IMPLEMENTED)

**Æther application.** One shell. Sections follow the project instructions: Command Center, PR-REX, Environment Laboratory, Research Studio, Recording and Replay, Evidence and Experiments, Performance Laboratory, Player Accessibility, System Administration. A section appears only when real behavior stands behind it.

**PR-REX player surfaces.** Control state, the active delegation in plain words, mode, environment, stop. Per-action detail is one level down; the running companion does not ask the player to verify each action.

**AACP views.** Read-only over GitHub data (tasks, candidate PRs, evidence tables, reviews, handoffs). Engineering-facing; never a runtime dependency of PR-REX.

## 7. Responsive and input

| Class | Width | Owner devices | Layout |
| --- | --- | --- | --- |
| Compact | < 600px | Phones, Fold 6 cover screen | Top bar with stop, mode banner, one column, bottom nav |
| Medium | 600–839px | Fold 6 inner screen, small tablets | Navigation rail, one column |
| Expanded | 840–1199px | Galaxy tablets, iPad landscape | Rail, content, context aside |
| Large | ≥ 1200px | MSI, Dell laptops | Labeled rail, content, wide aside |
| Spanning | two horizontal viewport segments | Fold 6 open in a hinge-aware browser | Content and aside on separate segments; nothing crosses the hinge |

Breakpoints follow Material 3 window-size classes. Spanning uses CSS Viewport Segments; without browser support the medium layout applies.

Every action is keyboard-reachable in visual order; focus is always visible; touch targets ≥44px (≥56px on player surfaces); no hover-only information; `prefers-reduced-motion` stops animation; no horizontal scroll at 320px; text scales to 200%. On player surfaces no action exists only as a touch or pointer gesture: controller and keyboard paths are first-class.

## 8. Implementation contract

- Edit `interfaces/shared/design/tokens.json`, run `python scripts/brand/build_tokens.py`, commit both. `pytest` guards sync, contrast and vocabulary.
- Components are plain CSS; global defaults scoped under `.ae`; no `!important` except the reduced-motion override.
- New component = class in `components.css` + gallery entry + row in §5.
- Application shell technology is undecided (D-006); until then, static HTML plus small vanilla JS.
